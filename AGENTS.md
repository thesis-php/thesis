# Thesis

Thesis builds asynchronous PHP packages on the thesis/async event loop, which uses PHP 8.6's `Io\Poll`.
The packages rework ideas from amphp and older Thesis packages from scratch. They use independent
implementations and have no dependencies on those packages. Thesis runs on Unix. Packages that need
64-bit PHP declare that requirement (`platform.md`).

## Layout

- Each `packages/<name>/` directory contains one package. A dedicated read-only repository publishes
  it as `thesis/<name>`. Only the package manifest, `package.php`, declares its description and dependencies.
  See `manifests.md`.
- `tools/monorepo/` is the monorepo tooling (`bin/monorepo`): generated files, the repositories of the packages,
  their split and their releases in CI. `tools/php-cs-fixer/` holds our custom PHP CS Fixer rules.
  The configs of the quality tools are in the root, the tools are dev dependencies in `vendor/`.
- `monorepo.php` is the root config. Files generated by `make sync` are never edited by hand.
- `agents/<topic>.md` holds rules and decisions that span packages, see "Topics".
  `ideas/` holds the roadmap and drafts of what is not built yet: plans, not decisions.

## Where knowledge lives

- `AGENTS.md` files and topics are the only memory that survives between sessions. Each one has rules
  (invariants) and decisions (what was rejected and why), and describes how things are now: when we rethink
  something, rewrite the existing text instead of appending a correction, the history is in git.
  Every rule is short, current and in the section it belongs to. Delete what became obsolete, merge duplicates.
- A rule is in the plain English of `php.md`. A rewrite for style keeps every fact, reason and `Rejected:`.
- An important finding (an invariant, a decision, a trap, a rejected approach) is written in the same change,
  without being asked, to the narrowest file that covers it: `AGENTS.md` of the package or tool if it is about one,
  a topic if it spans several, a new topic with a line in "Topics" if none fits. A topic over about 8 KB is split
  where its parts are needed apart.
- This file changes only when the user asks or a topic is added: parallel sessions would collide in it.
- A shared file (this file, a topic, the `Makefile`, a workflow) does not list the packages that share
  a manifest property (the PHP version, `php-64bit`). Such a list repeats the manifests and gets stale.
  Every session that adds a package to the list collides with the other sessions. The shared file states the rule.
  The manifest and the package `AGENTS.md` state the fact. A shared file names a package only as an example of a rule.
- `packages/<name>/AGENTS.md` is for those who *change* the package and is loaded only when you read its files.
  How to *use* a package is in its `README.md` or its `skills/`: read them before using a package
  you have not used yet in this session.
- Write `AGENTS.md` only, never `CLAUDE.md`: with the default settings, a `CLAUDE.md` in a directory makes
  Claude Code skip `AGENTS.md` there.
- What a tool enforces (`make fixer`, `make rector`) is not described: the tool fixes the code anyway.
  Why a custom rule is the way it is goes to the `AGENTS.md` next to the rule.

## Topics

`php.md` is imported below and always loaded. Read any other topic in `agents/` before the work it names:

- `tests.md`: writing or changing a test, mutation testing (`make infect`).
- `errors.md`: calling a PHP function that fails with a warning (files, streams, sockets, processes).
- `fibers.md`: keeping state per fiber, a test that depends on the order of callbacks.
- `manifests.md`: a manifest, a dependency, a new package or file of functions or constants, the public API of a package
  that others use, a feature added to or removed from a package (its `description` and `keywords` follow).
- `clients.md`: a client with work in the background (a connection, a reader loop, reconnects).
- `repositories.md`: the split, the repositories of the packages and their settings on GitHub.
- `versions.md`: the version of a package (`version:` of a manifest), a constraint on a monorepo package.
- `changelogs.md`: writing or editing a `CHANGELOG.md` of a package.
- `releases.md`: the release, the tags and the GitHub Releases of the split repositories.
- `platform.md`: code that depends on the operating system or on the size of `int`.
- `reviews.md`: reviewing a change, acting on the findings of a review.
- `benchmarks.md`: a benchmark, a change justified by one (`make bench`).

## Commands

Everything runs in Docker through `make`. `P=<name>` narrows a command to one package. Use it while you work,
the whole monorepo is for the final check.

- `make test P=async`, `make phpstan P=async`, `make fixer P=async`, `make rector P=async`
- `make sync` after changing a manifest or `monorepo.php`
- `make test` starts the services of `compose.yaml` (RabbitMQ) first (`make up`), `make down` stops them.
  An integration test fails without its service, it is never skipped: a skip hides a broken environment
- `make check` runs the checks of CI. CI also runs `make sync` and fails on any change in git,
  so commit the generated files. Everything runs on PHP 8.6. A package whose manifest allows an older PHP
  is also tested alone on every minor below 8.6 (`PHP_VERSION=8.2 make test-alone P=time`)

## Git

- Work and commit directly on `main`, do not create branches: the monorepo is in early development,
  branches only get in the way. This rule will change once others contribute.
- Commit only when asked, with a short imperative subject like the existing history. The user pushes.
- Undo a pushed commit with `git revert`, never by rewriting history.
- No `Claude-Session` or other trailers in commit messages and PR descriptions.
- An empty directory is kept by an empty `.gitignore`, never by `.gitkeep`. Delete it once the directory has files.

- `amqp`: AMQP 0.9.1 client for RabbitMQ: publisher confirms, consumers as iterators, reconnects. Requires: async, io, net, time.
- `async`: Structured concurrency for PHP fibers with its own event loop, task-tree cancellation and lazy initialization. Requires: dispatcher, source-location, time.
- `async-trace`: Tools around the trace of thesis/async: its events written as NDJSON and as lines of text for tests, who has cancelled a scope and why, code that blocks the others, waits that last too long. Requires: async, dispatcher, formatter, source-location, time.
- `cache`: Cache interface with Time\Duration TTLs, a local LRU cache and stampede protection by a keyed mutex. Requires: async, time.
- `demo`: A small HTTP server with console logging that shows how concurrent requests overlap. Requires: async, http, http-server, io, log, time.
- `dispatcher`: Synchronous event dispatcher: a listener gets the events of the type of its parameter, resolved once per class. Requires: formatter.
- `exceptionally`: Turns PHP errors into exceptions around a callable, safe when the callable suspends a fiber.
- `formatter`: Formats PHP values, classes, functions and parameters into short strings for error messages. Requires: source-location.
- `http`: HTTP messages shared by clients and servers: requests with query parameters, responses, headers, streamed bodies with trailers, and a strict HTTP/1.1 codec that refuses what request smuggling is made of. Requires: io.
- `http-client`: Asynchronous HTTP/1 client for HTTP and HTTPS with connection pooling, streaming bodies and trailers. Requires: http, io, net.
- `http-server`: Asynchronous HTTP/1 server for TCP and Unix sockets with streaming bodies, trailers, TLS and graceful shutdown. Requires: async, http, io, net, time.
- `io`: Fast binary I/O: typed byte buffer, non-blocking streams, stdio and a string reader. Requires: async, time.
- `log`: PSR-3 logger with a configurable clock, bounded buffering, and asynchronous JSON and colored console output. Requires: async, io, time.
- `net`: Non-blocking TCP and Unix sockets with TLS and an async DNS resolver, cancelled by the task tree. Requires: async, io, time.
- `phpstan-extension`: PHPStan extension for thesis packages: precise types where PHPDoc generics cannot express them.
- `source-location`: Where in the source code: a file and a line, the caller outside a library, the code of eval() resolved.
- `testo-plugin`: Testo plugins for thesis packages: tests in the event loop of thesis/async, real or virtual time, PHP errors as failures. Requires: async.
- `time`: Time\Duration polyfill for PHP >=8.2, shorthands like sec(5) and toMs(), strings like 1h30m, PSR-20 clocks.
